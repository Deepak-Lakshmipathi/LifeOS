- 2026-07-20 (#120): a mount/unmount setState test asserting on `result.current` after `unmount()` is VACUOUS — React 18 silently no-ops setState on an already-unmounted fiber (no throw, no re-render), so the assertion passes with OR without the guard. The ponytail-review reviewer caught it by MUTATION-TESTING: strip the guard, rerun, test still green = test proves nothing. Fix: assert on an observable side-effect that sits AFTER the guard (here `console.error` on the `.catch` path). Always mutation-test a regression test for a race/guard bug — a green test that also passes with the fix reverted is worthless. Do this yourself before dispatching review; it's ~2 min.

- 2026-08-04 (S63/S64): a **pre-resolved, owner-sanctioned DoD can specify two different state machines** and the suite can be blind to which one shipped. - 2026-08-05 (S66): **a test that counts collapsed work can pass on broken code for the opposite reason.** The naive `Promise.all([a.readFiles(), b.readFiles()])` form of "two consumers → one `git.pull`" would have gone GREEN on master: two concurrent dynamic `import()`s of the same `vi.mock`-ed specifier race in Vitest, one importer gets the real `isomorphic-git`, that caller dies on `ENOTFOUND` — and the surviving caller reports `pull === 1`, the exact number the fix is supposed to produce. Priming doesn't close the window; it only fires with >1 transport, i.e. only on pre-fix code. Fix: hold reader A *inside* `git.pull` before B starts, so the reads overlap but the imports never do. Generalize: when a test asserts a count went DOWN, ask what else could lower it — a crashed participant looks identical to a collapsed one.
